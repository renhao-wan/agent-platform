# 项目亮点：一亮点一文档

面试讲解与追问准备的材料。每篇结构一致：**30 秒版本 → 关键设计 → 深挖问答 → 实测证据 → 落地程度 → 后续拓展**。追问就往对应文档的"深挖问题清单"里找；被问"这算演示还是生产"就直接看"落地程度与生产差距"表。

| # | 亮点 | 文档 | 一句话 |
|---|---|---|---|
| ① | 三道权限闸门 | [01-权限闸门.md](01-权限闸门.md) | 模型只提议、不授权；执行点鉴权是唯一安全边界 |
| ② | 零改造接入：契约即工具 | [02-契约即工具.md](02-契约即工具.md) | OpenAPI 就是工具，持续对账而非一次性导入 |
| ③ | ReAct 显式循环与 SSE | [03-ReAct循环与SSE.md](03-ReAct循环与SSE.md) | 工具执行权在代码里，每步可插桩、可直播 |
| ④ | 上下文工程 + Agentic RAG | [04-上下文与知识库.md](04-上下文与知识库.md) | 分层记忆按需取回，知识由模型自主检索 |
| ⑤ | 边界与追问 | [05-边界与追问.md](05-边界与追问.md) | RBAC、全量导入、异构鉴权：承认没做，但要讲清为什么 |

## 讲解顺序建议

1. **先讲 ②**：零改造接入是"这个平台解决什么问题"最短的答案，也最容易引出后面三个亮点。
2. **再讲 ①**：接入之后马上遇到"AI 能不能乱调接口"，权限闸门是安全故事。
3. **然后讲 ③**：怎么让模型真的把工具用起来，以及为什么必须自己写循环。
4. **最后讲 ④**：工具能用之后，上下文成本和知识从哪来。

## 深挖用法

- 面试官问"你怎么保证不越权" → `01 §2、§4、§6`；
- 问"业务系统要改代码吗" → `02 §2-§4`；
- 问"为什么不用 LangChain / Spring AI 自动执行" → `03 §2、§4`；
- 问"上下文太长怎么办 / RAG 怎么做" → `04 §2-§5`；
- 问"多实例 / 服务发现 / 注册中心" → `02 §6-§7` + `05 §4` + `decisions/08-契约快照对账.md §9` + `decisions/09-来源发现与轮询.md`；
- 问"哪里是 demo 级 / 生产还缺什么" → 各篇的"落地程度与生产差距"表，横向汇总见 `05 §4`；
- 问"幂等 / 并发 / 重试 / 限流 / 资源清理怎么处理" → `05 §5`（工程稳定性清单，含明确未做项）；
- 问"是不是 RBAC / 生产怎么落地 / 异构鉴权 / 零改造是不是话术" → `05 §1-§4`。
