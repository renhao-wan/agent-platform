# 亮点 ②：零改造接入——契约即工具

> 一句话：业务系统只提供一份 OpenAPI 文档，平台把它变成工具并**持续对账**；业务系统对 AI 零感知。
>
> 代码入口：`gateway/registry/OpenApiImportServiceImpl`、`ContractSyncServiceImpl`、`ToolRegistryServiceImpl`、`GenericHttpForwarder`
> 背景决策：`docs/decisions/07-契约驱动授权.md`、`docs/decisions/08-契约快照对账.md`、`docs/decisions/09-来源发现与轮询.md`

## 1. 30 秒版本

```
业务系统（不改代码）                     平台
  /v3/api-docs  ──GET──▶  解析 operation → 工具定义 → 快照对账 → 写 MySQL
                                                           ↓
用户一句话 ──▶ ReAct 循环 ──▶ ToolGateway ──▶ 闸门校验 ──▶ HTTP 转发 ──▶ 业务系统 REST
```

四个关键点：

1. **契约即工具**：`operationId` 是工具名，`summary` 是工具描述，参数合成 `inputSchema`，`x-required-permission` / `x-require-confirm` 是权限声明。
2. **持续对账**：不是"导入一次"，而是每轮拿契约推导的期望状态与库内工具收敛（决策 08）。
3. **失败语义**：后端非 2xx / 超时 / 权限不足 / 用户拒绝，一律包装成文本观察回喂模型，循环不中断。
4. **来源可运营**：`GET /admin/sources` 看每个来源最后一次成功、差异计数与**下线条目/破坏性变更明细**（不只给数字）；`POST/PUT/DELETE /admin/sources` 运行时增删改来源；`POST /admin/sources/sync` 立即触发。来源移除即软下线其工具（保留行，复活可恢复）。

## 2. 契约 → 工具：具体规则

| 契约字段 | 工具字段 | 说明 |
|---|---|---|
| `operationId` | `name` | 缺失时按 method + path 生成 slug 兜底 |
| `summary` | `description` | **直接决定模型选工具的准确率**，必须是动作句（"查询指定时间段可用的会议室"） |
| path / query / requestBody | `input_schema` | 合并成一个 JSON Schema；`$ref` **就地展开** |
| `x-required-permission` | `required_permission` | 权限码（如 `booking:cancel`）；兼容裸值与 springdoc `@Extension` 的嵌套形状 |
| `x-require-confirm` | `require_confirm` | 敏感操作人工确认；`DELETE` 默认敏感 |
| `servers[0].url` 或配置 `baseUrl` | `url_template` 前缀 | 平台优先用抓取契约的 origin 或显式 baseUrl，契约自称的 host 不可信 |

`$ref` 必须内联：工具的 schema 是脱离原契约、单独发给模型的片段，`#/components/schemas/...` 在模型侧查不到，OpenAI 兼容接口会直接拒绝整轮请求。

**schema 保真度是有限的**：`requestBody` 的 JSON Schema 会完整展开；但 path/query 参数只保留 `type`、`format`、`description`，`enum`、`items`、`default` 等约束会丢失，`allOf/oneOf` 也不做归一化。结果不是"接不进来"，而是模型可能不知道枚举范围、数组元素类型，需要靠后端 400 和模型自愈兜底。生产接入应换成成熟的 OpenAPI 解析器或补一层 schema 归一化。

## 3. 为什么是"对账"而不是"导入"

| 问题 | 一次性导入 | 快照对账 |
|---|---|---|
| 接口删除 | 旧工具永远留下 | `present=0` 软下线 |
| `operationId` 改名 | 旧名留幽灵、新名新增 | 旧名下线、新名新增 |
| 运行中契约变更 | 必须重启 | 下一个周期自动收敛 |
| 管理员禁用工具 | 下次导入被打开 | `enabled` 与 `present` 分离，不被覆盖 |
| 抓取失败 | 可能删掉工具 | 保留 last-known-good |
| 同名冲突 | 悄悄顶掉 | 整份快照放弃，标 `CONFLICT` |

核心语义：**契约是期望状态，数据库是当前状态，对账负责收敛**。这是 Kubernetes controller 的模型，也是 MCP `tools/list_changed` 想表达的意思。

## 4. 深挖问题清单

**Q：为什么用轮询，不学 Nacos 用长连接/推送？**
被同步的是契约内容，变更只在发版时发生；业务系统不装任何平台 SDK，springdoc 也不会发"契约已变更"事件。要推送就得给每个业务系统加 webhook + 鉴权 + 重试，直接破坏零改造。轮询天然自愈、成本可忽略（3 个来源约每分钟 0.6 次 GET），契约未变时哈希比对后跳过。进化方向是"webhook 提及时性 + 轮询做兜底"，不是长连接。详见决策 09。

**Q：契约改了，平台多久知道？**
默认 5 分钟；`POST /admin/sources/sync` 或 `POST /admin/sources/{key}/sync` 可立即触发。启动时也会对账一次。

**Q：业务系统删了一个接口，工具会怎样？**
下一次成功对账后 `present=0`，不删行（保留 id 与审计），模型清单立即不再下发。接口恢复后下一次对账自动复活。

**Q：业务系统暂时宕机，工具会消失吗？**
不会。抓取失败只更新来源状态与 `last_error`，保留 `contract_hash` / `tool_count` / `last_success_at`，工具保持原状。真正调用时转发器返回失败文本，模型据此告知用户。

**Q：不同系统的 operationId 重名怎么办？**
同一个 `gatewayId` 下工具名是全局命名空间。对账发现同名工具仍由另一个来源以 `present=1` 声明时，整份快照放弃并标 `CONFLICT`，不会部分写入。接入时要约定命名唯一；系统更多时应该一系统一 `gatewayId`（当前配置是单网关，所有来源共用 `gw1`）。

**Q：为什么对账不先删后插？**
会改变工具 id，管理端启停、审计记录失去稳定标识，同步窗口内清单为空，人工 `enabled` 全丢。所以逐工具比对、软下线。

**Q：为什么失败不阻断同步？**
一次上游发布如果因为一个破坏性变更被卡住，整份契约停在旧版本，反而更危险。平台识别破坏性变更（端点、必填参数、类型、权限收紧/变更/撤销），以及新增写操作未声明权限（`PERMISSION_UNDECLARED`）并告警，但先同步。完整兼容性检查交给 oasdiff 这类专用工具。

**Q：怎么保证工具描述质量？**
`summary` 就是描述，所以要求业务方写成动作句。这是**业务方的责任**，平台不替它改写语义——一旦平台开始润色描述，就又在编码业务语义。

**Q：业务系统把失败装在 HTTP 200 里怎么办？**
平台只以非 2xx / 异常判定失败。业务异常装在 200 响应体里，模型会把"预订不存在"读成"订好了"。接口文档必须约定用状态码表达失败；唯一例外是幂等重放返回既有记录，语义上属于成功。

**Q：转发层怎么处理参数？**
`{param}` 从 arguments 取值并 URL 编码；GET/DELETE 余参拼 query；POST/PUT/PATCH 余参作 JSON body；schema 声明了 `properties.body` 时自动解包。响应 8KB 截断，防止打爆模型上下文。

**Q：私有契约需要登录才能访问怎么办？**
当前 `HttpContractFetcher` **不带任何凭证**，只能拉公开的 `/v3/api-docs`。这是生产接入最常见的阻塞之一：如果契约本身受保护，需要给来源增加"拉取凭证"（header / basic / mTLS），与调用凭证分开配置。当前没做，是因为演示系统的契约都是公开的。

**Q：服务凭证怎么存的？**
`tool_source.service_key_value` 存在 MySQL 里，管理端 API 只写不回显（`GET /admin/sources` 只披露"是否已配置"）。但落库是明文，生产应接 KMS / Secret Manager，并支持轮换与双凭证过渡。

**Q：管理员把契约地址填成内网地址怎么办？**
当前只校验是 http(s) URL，没有 SSRF 防护。`/admin/**` 需要管理员权限，风险面有限，但生产仍应做 egress allowlist、禁止 metadata/回环地址，并限制重定向。

**Q：支持 OpenAPI 3.1 / Swagger 2.0 吗？**
解析器按 `paths` / `components` / `requestBody` 的通用形状读取，3.0/3.1 的常见写法可以处理；Swagger 2.0（`definitions`、`parameters` 在 path 级）未适配。接入前应确认业务系统的 springdoc 版本。

**Q：新增一个业务系统要做什么？**
两种方式，都不用改平台代码、不用重启：① 在 `platform.gateway.sources` 加一项（`id` + `url`），下次启动种子进注册表；② 运行时 `POST /admin/sources` 登记来源（契约地址 + 可选调用基地址 + 服务凭证），保存即对账。之后由契约推导工具，管理员无需也不应手工编辑工具定义。

## 5. 实测证据

以下为本地实测，脚本未随仓库发布，但启动后可用管理端接口原样复现：

- 启动对账：booking 7 + expense 5 + repair 4 = 16 个工具；
- 再次对账：全部 `unchanged`，不写库（实测 `POST /admin/sources/sync` 返回 `unchanged 7/5/4`）；
- 软下线：手工快照导入一个工具后再次导入空契约，管理端显示 `present=false`，模型工具清单中消失；
- 人工禁用后再次对账，`enabled` 保持 `false`；
- 错误自愈：模型首次 `create` 时间格式错，后端 400，模型自动改格式重试成功。

## 6. 落地程度与生产差距

| 能力 | 代码与测试证据 | 完成度 |
|---|---|---|
| operation → 工具定义（含 `$ref` 内联） | `OpenApiImportServiceImpl`；`OpenApiImportServiceTest` | 接近生产（常见 OpenAPI 3.x；schema 保真度有限） |
| 快照对账：新增/更新/软下线、`present`/`enabled` 分离 | `ToolRegistryServiceImpl.applySnapshot`；`ToolRegistryServiceTest` / `ContractSyncServiceTest` | 接近生产（单实例） |
| 失败保留 last-known-good、同名冲突整份放弃 | `ContractSyncServiceImpl`；`ContractSyncServiceTest` | 接近生产 |
| 破坏性变更识别与告警 | `ToolChangeAnalyzer`；`ToolChangeAnalyzerTest` | 演示级（只覆盖 4 类，无通知渠道） |
| 泛化 HTTP 转发 | `GenericHttpForwarder`；`GenericHttpForwarderTest` / `GenericHttpForwarderTimeoutTest` | 接近生产（路径/query/body、8KB 截断、超时） |
| 来源运行时运营 | `ToolSourceAdminController` + `SourceRegistryService`；管理端测试 | 接近生产（CRUD、手工对账、状态明细） |
| 契约拉取鉴权 / 凭证托管 / SSRF 防护 | 未实现 | 演示级，正式接入前必须补 |
| 导入治理（默认启停、审批） | 新工具默认 `enabled=1` | 演示级，见 `05-边界与追问.md §1` |

**结论**：作为"一份契约变成一组可运营工具"的接入模式，单实例下已经接近生产；作为"任何企业系统都能直接接"的网关，还缺**契约拉取鉴权、凭证托管、SSRF 防护、导入审批**四块，这四块都属于接入治理，不是工具注册本身。

## 7. 后续拓展：问题与解决办法

| 拓展点 | 现在的问题 | 解决办法 | 触发条件 |
|---|---|---|---|
| 契约拉取鉴权 | 受保护的 `/v3/api-docs` 拉不到 | 来源增加 fetch 凭证（header/basic/mTLS），与调用凭证分离；凭证同样只写不回显 | 接入非公开契约 |
| 凭证托管 | 服务凭证明文落 MySQL | 接 KMS / Vault，库里只存引用；支持轮换与双凭证过渡 | 正式生产/等保要求 |
| SSRF 防护 | 管理员可填任意 http(s) 地址 | 来源 URL allowlist、禁止回环/内网 metadata、限制重定向、出站代理 | 管理端不是完全可信 |
| 导入审批 | 新工具默认启用，内部接口也会暴露 | 契约侧 `x-ai-exposed` / tag 过滤；或新工具默认 `enabled=0`，管理员确认后启用 | 接入核心系统前 |
| schema 保真 | query/path 丢 enum/items/default，allOf 未合并 | 换用成熟 OpenAPI 解析器，或补 schema 归一化与契约校验 | 业务参数复杂、模型频繁传错 |
| 破坏性变更通知 | 只写日志/管理端明细 | 接 Webhook / 邮件 / 企业 IM；按来源配置订阅人 | 多团队共用平台 |
| 多实例对账 | 每实例各自对账，重复抓取；缓存刷新仅进程内 | `tool_source` 增加租约列做来源级互斥；变更事件走消息总线或共享缓存失效 | 部署副本数 > 1 |
| 工具规模增长 | 全量工具每轮下发，token 线性增长 | 服务端检索/分层工具目录；`ToolSelector` 阈值调低并接入真实路由；按会话裁剪工具集 | 工具数 > 50 |
| 契约获取重试 | 失败等下一轮 5 分钟 | 指数退避重试 + 来源级熔断，避免宕机系统每轮都打 | 上游不稳定 |
