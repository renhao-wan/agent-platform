# ADR-003：上下文裁剪采用"滑动窗口 + 工具轨迹摘要"混合策略

日期：2026-09-29　状态：已采纳

## 背景

ReAct 多轮循环中，每轮工具返回都会进入上下文。会议预约场景单轮工具响应可达数 KB，
10+ 轮即可打爆模型上下文窗口，并显著推高成本。

## 备选方案

| 方案 | 问题 |
|---|---|
| 纯滑动窗口（只留最近 N 条） | 被裁掉的早期工具结论（如已确认的房间号）直接丢失，后续轮次可能重复查询或答错 |
| 纯摘要（每轮调模型压缩） | 每轮多一次 LLM 调用：成本翻倍、延迟翻倍，且摘要有失真风险 |
| RAG 重取（历史向量化，按需检索） | 引入向量库与嵌入调用，对话场景收益低于文档问答场景 |

## 决策

混合策略：粗估 token（chars/2，无嵌入调用成本）超过阈值（默认 6000）时——

1. 保留全部 system 前缀（系统提示词不可裁）；
2. 最近 6 条消息原样保留（当前任务的工作集）；
3. 更早的工具轨迹压缩为**一条确定性规则生成的摘要**（消息数 + 工具调用清单），
   摘要落 `checkpoint` 表（里程碑留痕），并以 SystemMessage 形式注入。

## 理由

- **确定性**：压缩规则可单测（见 ContextTrimmerTest），不引入模型不确定性；
- **零额外成本**：不产生额外 LLM 调用；
- **可实验**：TokenRecorder 打点 usage，开/关裁剪对比实验（M4）量化收益。

## 后果

- 被压缩轮次的细节数值不可还原——以"结论性摘要 + 里程碑"近似；
- 阈值与保留窗口均为配置项（`platform.agent.context-threshold`），可按模型窗口调整。
